Step 1: Configuration

첫 번째 관문: 직원 신분증과 본점 주소

아무나 본점 컴퓨터에 들어오면 안 되겠죠? 라즈베리파이에게 "직원 목걸이"를 걸어줍니다.

ELI5 비유: .env 파일은 계산원의 가방이에요!
.env 파일에는 본점 전화번호(BACKEND_URL)와 나를 증명하는 비밀 암호 목걸이(DEVICE_API_KEY) 딱 2개가 들어있어요.
pi/.env 설정 예시 
# 본점(백엔드) 주소
# 같은 노트북 안에서 테스트할 때는 localhost
BACKEND_URL=http://localhost:8000

# 라즈베리파이에서 다른 PC 백엔드로 보낼 때 (예시 IP)
# BACKEND_URL=http://192.168.0.15:8000

# 계산원 직원 신분증 (헤더에 들어갈 API KEY)
DEVICE_API_KEY=dev-device-key-change-in-production

# 지금은 하드웨어가 없으므로 mock 모드로 실행
DEVICE_MODE=mock

꼭 지켜야 할 약속 3가지

  • 백엔드 친구와 상의하기: 백엔드 친구에게 "백엔드 켜진 PC의 IP 주소가 뭐야?"라고 물어보고 BACKEND_URL에 적기.
  • 신분증 키 일치시키기: 백엔드의 DEVICE_API_KEY와 파이의 키가 한 글자도 틀리지 않아야 본점에서 문을 열어줍니다 (401 에러 방지).
  • 깃허브에 올리지 않기: .env 파일은 비밀번호라 깃허브에 안 올라가도록 .gitignore에 적혀 있으니 안심하세요.
Step 2: Communication

본점에 노크하기 (REST API란?)

컴퓨터끼리 편지를 주고받는 표준 양식이 바로 REST API (JSON)입니다.

우리가 보내는 쪽지 (Request)

파이썬의 requests라는 심부름꾼 라이브러리를 써서 본점에 물어봅니다.

GET /api/v1/atm/verify/VP-000003
헤더: X-Device-Api-Key: dev-device-key...
본점이 주는 답장 (JSON Response)

본점은 항상 깔끔하게 이름표가 붙은 JSON 형식으로 답장을 줍니다.

{
  "data": {
    "risk_level": "DANGER",
    "action": "BLOCK",
    "summary": "검찰 사칭 의심"
  }
}
이미 완성되어 있는 치트키: `backend_client.py`
복잡하게 일일이 코드를 짤 필요 없어요! 우리 프로젝트의 pi/backend_client.py 파일에
client.verify_session("VP-000003") 딱 한 줄만 부르면 알아서 본점에 다녀오는 착한 함수가 이미 준비되어 있습니다!
Step 3: QR Code Parsing

QR 코드에서 비밀번호 찾기

QR 코드는 사진이 아니라 글자 덩어리입니다. 카메라가 읽은 글자에서 필요한 번호만 쏙 꺼냅니다.

왜 QR에 개인정보나 사기 문자 내용을 통째로 넣지 않을까요?
누군가 QR을 훔쳐보거나 위조할 수 있기 때문이에요! QR에는 오직 접수 번호표(`session_id`) 하나만 적어둡니다.
진짜 위험한지 아닌지는 우리 ATM이 직접 본점에 물어봐야만 알 수 있습니다 (보안 원칙).

QR에서 나올 수 있는 3가지 모양

형태 QR 내용 예시 설명
표준 (기본) {"session_id": "VP-000003"} 스마트폰 앱이 화면에 띄우는 정상 QR
오프라인 백업 {"session_id":"...", "risk_level":"DANGER"} 인터넷이 끊겼을 때만 비상용으로 사용
단순 문자열 VP-000003 개발자가 키보드로 테스트할 때 쓰는 형태
pi/atm_controller.py 파싱 마법 함수 
# parse_qr_payload() 함수를 쓰면 끝!
from atm_controller import parse_qr_payload

# 1. QR에서 읽은 글자를 넣는다
raw_qr = '{"session_id": "VP-000003"}'
payload = parse_qr_payload(raw_qr)

# 2. 접수 번호만 쏙 꺼낸다
print(payload.session_id)
# 출력 결과: VP-000003  (성공!)
Step 4: Hands-on Practice

핵심 실습: 본점에 묻고 print()로 반응하기

하드웨어 연결 없이도 백엔드와 완벽하게 짝을 맞추는 10줄의 마법 코드입니다!

test_atm_step1.py (직접 실행해보기) 
from backend_client import BackendClient

client = BackendClient()

# 1. QR에서 읽은 세션 번호로 본점에 물어보기
session_id = "VP-000003"
print(f"[*] 본점에 {session_id} 확인 요청 중...")

result = client.verify_session(session_id)
action = result.get("action")  # ALLOW 또는 BLOCK

# 2. 결과에 따라 모터 대신 print()로 동작시키기!
if action == "ALLOW":
    print("====================================")
    print(" [ATM] 안전한 거래입니다.")
    print(" [모터 대신 print] 찰칵! 현금 배출구가 열렸습니다!")
    print("====================================")
elif action == "BLOCK":
    print("====================================")
    print(" [ATM 경고] 보이스피싱 의심 거래 감지!")
    print(" [모터 대신 print] 삐삐삐! 현금 배출을 강력 차단합니다!")
    print(f" 의심 사유: {result.get('summary')}")
    print("====================================")
SAFE 판정일 때 action: "ALLOW"
고객이 안심하고 돈을 뽑을 수 있도록 서보모터(배출구)를 여는 신호를 보냅니다. (지금은 print()로 확인!)
CAUTION 판정일 때 action: "VERIFY"
조금이라도 의심되면 일단 배출을 멈추고 추가 확인 절차로 연결합니다.
DANGER 판정일 때 action: "BLOCK"
절대로 돈이 나오지 않도록 차단하고, 화면을 콜센터 연결 상태(CALL_CENTER)로 바꿉니다!
Step 5: Polling Cycle

상담원 확인 기다리기 (폴링이란?)

출금이 막혔을 때, 라즈베리파이는 상담원이 풀어줬는지 어떻게 알 수 있을까요?

ELI5 비유: "엄마, 밥 다 됐어?" 계속 물어보는 아이
폴링(Polling)이란 주기적으로 "결정하셨나요?"하고 노크하는 기술이에요.
ATM이 2~3초마다 본점에 GET /api/v1/atm/session-status/{session_id}를 물어보다가,
상담원이 RELEASED(해제) 도장을 찍어주면 그 즉시 차단을 풀고 돈을 내보냅니다.
폴링 시연 루프 코드 
import time
from backend_client import BackendClient

client = BackendClient()
session_id = "VP-000003"

print("[*] 콜센터 상담원의 판단을 기다리는 중...")

while True:
    status = client.read_session_status(session_id)
    resolution = status.get("callcenter_resolution")
    
    if resolution == "RELEASED":
        print(" [상담원] 정상 거래로 확인되어 제한을 해제합니다!")
        print(" [모터 대신 print] 찰칵! 출금 가능 상태로 전환!")
        break
    elif resolution == "MAINTAINED":
        print(" [상담원] 보이스피싱 확정! 출금을 영구 차단합니다.")
        break
    else:
        print(" ...아직 상담원 확인 중입니다 (2초 후 재확인)...")
        time.sleep(2)

콜센터 연동 테스트 꿀팁

1. 콜센터 담당 학생과 짝꿍 플레이:
내가 위 파이썬 스크립트를 켜두면 콘솔에 "...확인 중..."이 계속 뜹니다.

2. 웹 화면에서 [해제] 버튼 클릭:
콜센터 담당 친구가 웹 브라우저 (/callcenter)에서 해당 세션의 [정상 거래 확인 (제한 해제)] 버튼을 딸깍 누릅니다.

3. 내 터미널에 풀리는 기적 목격:
그 순간 내 라즈베리파이 터미널에 "찰칵! 출금 가능!"이 찍히면 둘의 통신이 100% 완벽하게 연결된 것입니다!

Step 6: Troubleshooting

"앗 에러가 났어요!" 당황하지 마세요

개발 중에 만나는 빨간 글씨는 고장 난 게 아니라 컴퓨터가 보내는 친절한 신호입니다.

Connection Refused
연결할 수 없음

원인: 본점(백엔드 서버)이 아직 안 켜져 있거나, BACKEND_URL에 적힌 IP 주소가 틀렸어요.

해결: 백엔드 담당 친구에게 "FastAPI 서버 켜져 있어?" 확인하고 IP 주소를 다시 적어주세요.

401 Unauthorized
신분증 불일치

원인: 라즈베리파이의 DEVICE_API_KEY와 백엔드의 키가 서로 달라요.

해결: .env 파일 속 DEVICE_API_KEY 값을 백엔드 친구의 .env와 똑같이 복사해서 붙여넣으세요.

404 Not Found
세션을 찾을 수 없음

원인: QR에 적힌 session_id가 본점 DB에 등록되지 않은 번호예요.

해결: 스마트폰 웹(/messages)에서 실제로 의심 문자 분석을 돌린 뒤 새로 발급된 QR 번호로 테스트하세요.

에러 해결 공식: "IP 확인 ➡️ 키 확인 ➡️ 세션 번호 확인"
이 3가지만 체크하면 통신 에러의 99%는 5분 안에 해결됩니다!
