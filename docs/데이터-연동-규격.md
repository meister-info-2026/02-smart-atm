# 데이터 연동 규격 (앱 ↔ 백엔드 ↔ ATM ↔ 콜센터)

> PRD 1주차 산출물 "앱 ↔ AI ↔ QR ↔ ATM 데이터 규격 확정"에 해당하는 문서다.
> 각 담당자는 이 규격에만 맞추면 서로의 코드를 몰라도 단독 개발·테스트할 수 있다.
> 변경할 때는 팀 전체에 먼저 공유한다 (PRD 권장사항).

## 0. 공통 규칙

### 응답 형식 (`.agents/rules/api-rules.md`)
```jsonc
// 성공
{ "data": { ... } }
// 실패
{ "error": { "code": "SESSION_NOT_FOUND", "message": "등록되지 않은 QR입니다." } }
```
상태 코드: 인증 실패 401 / 권한 없음 403 / 유효성 실패 422 / 리소스 없음 404

PRD 5.2·5.8의 예시 JSON(`{"risk_level": ..., "reasons": [...]}`)은 이 `data` 안에
그대로 들어간다.

### 인증 분리 (반드시 지킬 것)

| 대상 | 방식 | 헤더 |
|---|---|---|
| 사용자향 (앱·콜센터 화면) | JWT | `Authorization: Bearer <token>` |
| 디바이스향 (라즈베리파이 ATM) | 디바이스 API 키 | `X-Device-Api-Key: <key>` |

`users.role`은 `user`(일반 사용자) 또는 `agent`(콜센터 상담원)다.
`/api/v1/callcenter/**`는 **`agent`만** 접근할 수 있다 — 제한을 받은 사용자가 스스로
제한을 푸는 것을 막기 위해서다 (PRD 8: 최종 확인은 사람=상담원이 한다). 일반 사용자가
호출하면 `403 FORBIDDEN`이다.

두 경로를 섞지 않는다. 디바이스 키로 사용자 API를 호출하면 401, 사용자 JWT로 ATM
API를 호출해도 401이다 (`backend/tests/test_api_flow.py`에서 검증한다).

### 공통 값

| 구분 | 값 |
|---|---|
| `risk_level` | `SAFE`(안전) · `CAUTION`(의심) · `DANGER`(위험) |
| `risk_score` | 0~100 (키워드 범주별 가중치 합산, 100 상한) |
| 등급 경계값 | 0~29 SAFE / 30~69 CAUTION / 70~100 DANGER |
| `action` | `ALLOW` · `VERIFY` · `BLOCK` |
| `atm_status` | `READY` · `WITHDRAW_ENABLED` · `WITHDRAW_BLOCKED` · `CALL_CENTER` |
| `callcenter_resolution` | `RELEASED`(해제) · `MAINTAINED`(유지) · `null`(미처리) |
| `session_id` | `VP-` + 6자리 (예: `VP-000003`) |
| 시각 | DB에는 UTC로 저장, 화면 표시할 때 변환 |

## 1. 사용자향 API (JWT)

| 기능 | 메서드 · 경로 |
|---|---|
| 로그인 | `POST /api/v1/auth/login` |
| 내 정보 | `GET /api/v1/users/me` |
| 친구 목록 | `GET /api/v1/friends` |
| 채팅방 목록 | `GET /api/v1/chats` |
| 채팅방 메시지 | `GET /api/v1/chats/{chat_id}/messages` |
| 메시지 추가 | `POST /api/v1/chats/{chat_id}/messages` |
| **직접 입력 문자 분석** | `POST /api/v1/analysis` |
| **채팅 메시지 분석** | `POST /api/v1/analysis/chats/{chat_id}` |
| 분석 결과 조회 | `GET /api/v1/analysis/{analysis_id}` |
| ATM 세션(QR 재료) 조회 | `GET /api/v1/analysis/{analysis_id}/atm` |
| 콜센터 세션 목록 (`agent` 전용) | `GET /api/v1/callcenter/sessions?only_open=true` |
| 콜센터 세션 상세 (`agent` 전용) | `GET /api/v1/callcenter/sessions/{session_id}` |
| 콜센터 확인 처리 (`agent` 전용) | `POST /api/v1/callcenter/resolve/{session_id}` |

### 문자 분석
```jsonc
// 요청 — POST /api/v1/analysis
{ "message": "검찰입니다. 계좌가 범죄에 연루되었습니다..." }

// 요청 — POST /api/v1/analysis/chats/{chat_id}
{ "message_id": 2 }        // 생략하면 그 채팅방의 최신 메시지를 분석한다
```
```jsonc
// 응답
{
  "data": {
    "analysis_id": 3,
    "risk_level": "DANGER",
    "risk_score": 100,
    "reasons": ["기관 사칭 표현 감지", "현금 인출 요구 감지"],
    "summary": "기관 사칭 표현 및 현금 인출 요구 감지",
    "detected_at": "2026-09-04T05:13:36",
    "message_text": "검찰입니다. ...",
    "session_id": "VP-000003",
    "atm_action": "BLOCK"
  }
}
```
> ATM 세션은 `SAFE`일 때도 만든다 — ATM에서 "제한 없음"을 확인하는 정상 시나리오
> (PRD 9.1)도 서버 검증을 거치기 때문이다.

### 콜센터 확인 처리
```jsonc
// POST /api/v1/callcenter/resolve/VP-000003
{ "resolution": "RELEASED", "note": "본인 확인 완료, 정상 거래" }
```
`RELEASED`면 `atm_status`가 `WITHDRAW_ENABLED`로, `MAINTAINED`면 `WITHDRAW_BLOCKED`로
바뀐다. **시스템이 스스로 바꾸지 않는다** (`db-rules.md` 경보성 디바이스 원칙).

## 2. QR 규격 (PRD 6.2)

프론트엔드가 화면에 표시하는 QR의 내용은 이것뿐이다.
```json
{ "session_id": "VP-000003" }
```
- 위험 등급·탐지 시각·요약·개인정보는 **QR에 넣지 않는다.** ATM이 서버에서 조회한다
  (위변조 위험과 개인정보 노출을 줄이기 위한 PRD 권장사항)
- 네트워크 없이 시연해야 할 때에 한해 `{"session_id": "...", "risk_level": "DANGER"}`
  형태를 쓸 수 있다. ATM은 서버에 닿지 못할 때만 이 값을 쓴다
- 순수 문자열 `VP-000003`도 허용한다 (스캐너 테스트용)
- 위 셋 중 어느 것도 아니면 **거래 제어 데이터로 쓰지 않고** 오류를 안내한다 (TC-04)

## 3. 디바이스향 API — 라즈베리파이 ATM (`X-Device-Api-Key`)

### QR 서버 검증 (PRD 5.8 · OF-03 필수)
```
GET /api/v1/atm/verify/{session_id}
```
```jsonc
{
  "data": {
    "session_id": "VP-000003",
    "risk_level": "DANGER",
    "risk_score": 100,
    "action": "BLOCK",
    "atm_status": "WITHDRAW_BLOCKED",
    "detected_at": "2026-09-04T05:13:36",
    "summary": "기관 사칭 표현 및 범죄 연루 언급 감지",
    "reasons": ["기관 사칭 표현 감지", "..."]
  }
}
```
없는 세션이면 `404 SESSION_NOT_FOUND`.

### 스캔 결과 보고
```
POST /api/v1/atm/scan
{ "session_id": "VP-000003", "atm_status": "CALL_CENTER" }
```
`scanned_at`을 기록하고 WebSocket으로 콜센터 화면에 브로드캐스트한다.

### 콜센터 확인 폴링
```
GET /api/v1/atm/session-status/{session_id}
```
```jsonc
{
  "data": {
    "session_id": "VP-000003",
    "atm_status": "CALL_CENTER",
    "callcenter_resolution": null,
    "action": "BLOCK"
  }
}
```
상담원이 `RELEASED`를 기록하면 `action`이 `ALLOW`로 바뀐다.

### 출금 시도 보고 (FR-08/FR-09 시연 근거)
```
POST /api/v1/atm/withdraw-attempt/{session_id}?dispensed=false
```
배출 여부 **판단 자체는 라즈베리파이가 로컬에서** 하고, 여기서는 `control_log`에
기록만 남긴다.

## 4. ATM 로컬 데몬 API (7인치 화면 ↔ 라즈베리파이)

`pi/main.py`가 파이 안에서 `http://localhost:8100`으로 띄운다. 인터넷이 끊겨도
동작해야 하므로 인증을 두지 않는다(파이 내부에서만 접근).

| 메서드 · 경로 | 설명 |
|---|---|
| `GET /state` | 현재 ATM 상태 (화면이 1초마다 폴링) |
| `POST /qr` | QR 문자열을 직접 넣어 처리 (`{"data": "..."}`, 카메라 없이 시연할 때) |
| `POST /withdraw` | 출금 버튼 (`{"amount": 50000}`) |
| `POST /call-center` | 콜센터 확인 단계로 전환 |
| `POST /reset` | 대기 상태로 초기화 |

```jsonc
// GET /state 응답
{
  "data": {
    "state": "WITHDRAW_BLOCKED",
    "session_id": "VP-000003",
    "risk_level": "DANGER",
    "risk_score": 100,
    "reasons": ["기관 사칭 표현 감지"],
    "summary": "...",
    "guidance": "보이스피싱 위험이 확인되어 현금 출금을 잠시 멈췄습니다",
    "can_withdraw": false,
    "last_error": null,
    "offline": false
  }
}
```

## 5. WebSocket 이벤트 (`ws://<backend>/ws`)

콜센터 화면이 구독한다. 세 가지 형태가 온다.
```jsonc
{ "type": "atm_scan", "session_id": "VP-000003", "risk_level": "DANGER",
  "risk_score": 100, "atm_status": "CALL_CENTER" }

{ "type": "withdraw_attempt", "session_id": "VP-000003", "dispensed": false,
  "atm_status": "WITHDRAW_BLOCKED", "risk_level": "DANGER" }

{ "type": "callcenter_resolved", "session_id": "VP-000003",
  "callcenter_resolution": "RELEASED", "atm_status": "WITHDRAW_ENABLED" }
```

## 7. 하네스 스킬 문서와의 대응

`.agents/skills/callcenter-session-integration/SKILL.md`가 예시로 든 경로와 실제
구현 경로가 다르다. PRD 권장사항("`/api/v1` 구조를 유지한다")을 따랐기 때문이다.

| 스킬 문서 | 실제 구현 |
|---|---|
| `POST /api/analyze` | `POST /api/v1/analysis` (직접 입력) / `POST /api/v1/analysis/chats/{chat_id}` (채팅 선택) |
| `analysis_sessions` 테이블 | `analysis_results`(분석) + `atm_sessions`(ATM 세션) 두 테이블로 분리 — PRD 5.9 테이블명과 `GET /api/v1/analysis/{id}/atm` 구조에 맞췄다 |
| `POST /api/v1/atm/scan` | 동일 |
| `GET /api/v1/atm/session-status/{session_id}` | 동일 |
| `POST /api/v1/callcenter/resolve/{session_id}` | 동일 |
| QR에 응답 전체를 넣는다 | QR에는 `session_id`만 넣고 서버에서 조회한다 (PRD 6.2가 더 최신) |
