# 1부. 설치

## 1-1. 먼저 깔아야 할 프로그램

| 프로그램 | 버전 | 확인 명령 | 비고 |
|---|---|---|---|
| Python | **3.11 또는 3.12** | `py --version` | "Add python.exe to PATH" 체크 필수. 3.10 미만은 안 된다(`int \| None` 문법 사용) |
| Node.js | **20 LTS 이상** | `node --version` | Next.js 14가 18.17 이상을 요구한다 |
| Git | 최신 | `git --version` | |
| XAMPP (MySQL) | 8.x | XAMPP 제어판에서 MySQL Start | MySQL Server 단독 설치도 무방 |
| VS Code 또는 Antigravity | 최신 | | |

## 1-2. PowerShell 실행 정책 풀기 (가장 먼저)

이걸 안 하면 가상환경 활성화(`Activate.ps1`)가 `PSSecurityException`으로 막힌다.
PowerShell을 열고 **딱 한 번만** 실행한다.

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

한글 출력이 깨지면 같은 창에서:

```powershell
chcp 65001
$env:PYTHONUTF8 = "1"
```

## 1-3. 저장소 받기

```powershell
cd $HOME\Documents
git clone https://github.com/foxjini/agent-vibe-coding-starter-kit2.git
cd agent-vibe-coding-starter-kit2
git checkout atm
```

> `atm` 브랜치에 이번 구현이 들어 있다. `main`에는 없다.

## 1-4. 파이썬 가상환경 하나로 통합 (권장)

백엔드와 ATM 데몬을 한 PC에서 같이 개발하므로, **저장소 루트에 가상환경 하나**를
만들고 두 requirements를 함께 설치하는 게 가장 편하다. (라즈베리파이 실기기에는
`pi/requirements.txt`만 따로 설치한다 —
`docs/스마트금융보안ATM-실행-가이드.md` 4-2절 참고)

```powershell
# 저장소 루트에서
py -3.11 -m venv venv     # 3.12를 쓴다면 py -3.12, 버전이 하나뿐이면 그냥 py
.\venv\Scripts\Activate.ps1

python -m pip install --upgrade pip
pip install -r backend\requirements.txt -r pi\requirements.txt
pip install "qrcode[pil]"      # QR 이미지 생성 — 테스트와 시연 검증 스크립트에서 쓴다
```

프롬프트 앞에 `(venv)`가 붙으면 성공이다. **새 PowerShell 창을 열 때마다**
`.\venv\Scripts\Activate.ps1`을 다시 실행해야 한다.

설치 확인:

```powershell
python -c "import fastapi, sqlalchemy, cv2, qrcode, requests; print('OK')"
```

## 1-5. 프론트엔드 설치

```powershell
cd frontend
npm install
cd ..
```

## 1-6. MySQL 데이터베이스 만들기

XAMPP 제어판에서 **MySQL을 Start** 한 뒤:

```powershell
Get-Content backend\db\init.sql | mysql -u root
```

`mysql: command not found`가 나면 둘 중 하나로 한다.

```powershell
# 방법 A — 전체 경로 지정
Get-Content backend\db\init.sql | & "C:\xampp\mysql\bin\mysql.exe" -u root
```

**방법 B (가장 확실함)** — 브라우저에서 `http://localhost/phpmyadmin` → **SQL 탭** →
`backend\db\init.sql` 내용을 통째로 붙여넣고 실행.

확인: phpMyAdmin에 `smart_atm` 데이터베이스와 그 안에 `users`, `analysis_results`,
`atm_sessions`, `devices` 등 9개 테이블이 보이면 된다.

## 1-7. `.env` 파일 3개 만들기

```powershell
Copy-Item backend\.env.example  backend\.env
Copy-Item frontend\.env.example frontend\.env.local
Copy-Item pi\.env.example       pi\.env
```

직접 만들어 넣어야 하는 값 두 개를 생성한다.

```powershell
# JWT_SECRET (32바이트 이상)
python -c "import secrets; print(secrets.token_urlsafe(48))"

# DEVICE_API_KEY
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

세 파일을 메모장이나 VS Code로 열어 채운다.

**`backend\.env`**
```ini
DEVICE_MODE=mock
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root
DB_PASSWORD=            # XAMPP 기본값은 비어 있다
DB_NAME=smart_atm
JWT_SECRET=<위에서 만든 첫 번째 값>
DEVICE_API_KEY=<위에서 만든 두 번째 값>
CORS_ORIGINS=http://localhost:3000
SEED_DEFAULT_PASSWORD=      # 비워두면 demo1234
```

**`pi\.env`** — PC에서 개발할 때는 카메라 없이 돌린다.
```ini
BACKEND_URL=http://127.0.0.1:8000
DEVICE_API_KEY=<backend\.env와 똑같은 값>
DEVICE_MODE=mock
ENABLE_CAMERA=false
ATM_DAEMON_PORT=8100
CALL_CENTER_POLL_SECONDS=3
```

**`frontend\.env.local`** — 기본값 그대로 두면 된다.
```ini
NEXT_PUBLIC_API_BASE_URL=http://localhost:8000
NEXT_PUBLIC_WS_URL=ws://localhost:8000/ws
NEXT_PUBLIC_ATM_DAEMON_URL=http://localhost:8100
```

> ⚠️ `CORS_ORIGINS`의 주소와 브라우저 주소창의 주소를 **똑같이** 맞춘다.
> `localhost`와 `127.0.0.1`은 브라우저가 서로 다른 출처로 취급한다. 어긋나면
> 화면은 뜨는데 목록만 계속 비어 있다.
>
> ⚠️ `.env` 파일은 커밋되지 않는다(`.gitignore`). 실제 시크릿 값을 AI 채팅창에
> 붙여넣지 않는다 — 한 번이라도 붙여넣었으면 새로 만든다.

# 3부. 테스트 방법

## 3-1. 자동 테스트 — 서버를 안 띄워도 된다

저장소 **루트**에서:

```powershell
.\venv\Scripts\Activate.ps1
pytest
```

`49 passed`가 나오면 정상이다.

| 파일 | 무엇을 지키는가 |
|---|---|
| `backend/tests/test_rules.py` | TC-01~TC-03, 위험 등급 경계값, CAUTION=VERIFY |
| `backend/tests/test_api_flow.py` | 인증 분리, 전체 API 흐름, TC-04·TC-05, 콜센터 권한 |
| `pi/tests/test_atm_controller.py` | **FR-09** — 위험 상태에서 배출 장치가 안 움직이는지 |
| `pi/tests/test_qr_end_to_end.py` | 실제 QR 이미지를 만들어 다시 읽는 왕복 검증 |

자주 쓰는 형태:

```powershell
pytest backend\tests\test_rules.py           # 한 파일만
pytest -k "danger"                            # 이름에 danger가 들어간 것만
pytest -q                                     # 짧게
pytest -x                                     # 첫 실패에서 멈춤
pytest -vv --tb=long                          # 실패 원인 자세히
```

> 테스트는 임시 SQLite 파일을 쓴다. MySQL을 안 켜도 돌아가고, 실제 `smart_atm`
> 데이터베이스를 건드리지 않는다.

## 3-2. 통합 시연 검증 — 서버를 띄운 상태에서

창 1(백엔드)과 창 3(ATM 데몬)이 떠 있는 상태에서 **네 번째 창**을 열고:

```powershell
.\venv\Scripts\Activate.ps1
$env:DEVICE_API_KEY = "<backend\.env에 넣은 값>"
$env:SEED_DEFAULT_PASSWORD = "demo1234"
python scripts\demo_e2e.py
```

5개 시나리오가 한 줄씩 `OK`로 찍히고 마지막에 통과 메시지가 나온다.

1. 정상 문자 → 출금 가능, 실제 배출
2. 보이스피싱 문자 → 출금 차단 → 콜센터 해제 → 배출
3. 잘못된 QR → 거래 제어에 사용 안 함
4. 사용자는 스스로 제한을 못 푼다
5. 인증 분리(디바이스 키 ↔ 사용자 JWT)

실제 QR PNG를 만들어 OpenCV로 다시 읽는 것까지 포함한다.

## 3-3. 눈으로 확인하는 체크리스트

자동 테스트가 못 잡는 것(화면 배치, 글씨 크기, 색)은 직접 본다.

- [ ] `/messages`에서 "검찰입니다..." 문자를 골라 검사 → **위험 100점**, 근거 4개
- [ ] 결과 화면에 QR이 뜨고 아래에 `VP-000003` 같은 세션 번호가 보인다
- [ ] 창 3의 로그를 보면서, QR 내용을 데몬에 직접 넣어 본다
      ```powershell
      Invoke-RestMethod -Uri http://localhost:8100/qr -Method Post `
        -ContentType "application/json" `
        -Body '{"data": "{\"session_id\": \"VP-000003\"}"}'
      ```
      (PowerShell에서는 **작은따옴표** 안에 JSON을 넣어야 `\"`가 그대로 전달된다.
      `curl.exe`로 하면 따옴표 탈출이 까다로워 자주 실패한다.)
- [ ] `/atm` 화면이 **빨갛게** 바뀌고 큰 글씨로 "현금 출금을 잠시 멈췄습니다"
- [ ] 50만 원 버튼을 눌러도 "현금이 나오지 않습니다" — 창 3 로그에 `출금 차단`
- [ ] "상담원 확인 요청하기" → `/callcenter`에 세션이 뜬다 (배지 "실시간 연결됨" 초록)
- [ ] "정상 거래 — 제한 해제" → 몇 초 뒤 `/atm`이 출금 가능으로 바뀐다
- [ ] 브라우저 폭을 375px로 줄여도 레이아웃이 안 깨진다

## 3-4. 뭔가 안 될 때 좁혀 들어가는 순서

아래에서부터 위로 하나씩 확인하면 원인이 빨리 잡힌다.

1. `pytest` → 여기서 깨지면 **로직 문제**다. 서버·브라우저는 볼 것도 없다
2. `http://localhost:8000/health` → 백엔드가 살았는가
3. `http://localhost:8000/health/db` → DB에 붙었는가
4. `http://localhost:8100/state` → ATM 데몬이 살았는가
5. 브라우저 **F12 → Console/Network** → 빨간 줄이 있으면 CORS나 주소 문제다
6. `python scripts\demo_e2e.py` → 어느 시나리오에서 `FAIL`인지 본다

# 4부. 수정 보완 방법

## 4-1. 어디를 고치면 무엇이 바뀌나

| 바꾸고 싶은 것 | 고칠 파일 | 확인 방법 |
|---|---|---|
| 위험 키워드 추가·삭제 | `backend/analysis/keywords.py` | `pytest backend\tests\test_rules.py` |
| 범주별 가중치 | `backend/analysis/keywords.py`의 `weight` | 같은 위 |
| 위험 등급 경계값 | `backend/config.py`의 `RISK_SAFE_MAX`, `RISK_CAUTION_MAX` | 같은 위 (경계값 테스트도 함께 고쳐야 함) |
| CAUTION일 때 ATM 정책 | `backend/analysis/rules.py`의 `RISK_LEVEL_TO_ACTION` | `pytest` 전체 |
| ATM 화면 안내 문구 | `pi/atm_controller.py`의 `GUIDANCE` | 창 3 재시작 후 `/atm` |
| 결과 화면 안내 문구 | `frontend/app/result/[analysisId]/page.tsx`의 `GUIDANCE` | 브라우저 새로고침 |
| 출금 금액 버튼 | `frontend/app/atm/page.tsx`의 `AMOUNTS` | 브라우저 새로고침 |
| ATM 화면 갱신 주기 | 같은 파일의 `POLL_INTERVAL_MS` (기본 1000ms) | 같은 위 |
| 콜센터 폴링 주기 | `pi/.env`의 `CALL_CENTER_POLL_SECONDS` | 창 3 재시작 |
| GPIO 핀 번호 | `pi/.env` (`SERVO_GATE_PIN` 등) — **코드 수정 불필요** | 라즈베리파이에서 |
| 서보 각도·동작 시간 | `backend/iot/hardware_provider.py`의 `SERVO_OPEN_ANGLE`, `DISPENSE_HOLD_SECONDS` | 라즈베리파이에서 |
| 시연용 계정·문자 | `backend/db/seed.py`의 `DEMO_USERS`, `DEMO_CHATS` | `python -m db.seed` 다시 실행 |
| 세션 번호 형식 | `backend/config.py`의 `SESSION_ID_PREFIX`, `SESSION_ID_DIGITS` | `pytest` |

## 4-2. 수정 레시피 3가지

### 레시피 A — 위험 키워드 추가하기

가장 자주 하게 될 수정이다. `backend/analysis/keywords.py`에서 해당 범주의
`keywords` 튜플에 문자열만 추가한다.

```python
RiskCategory(
    code="IMPERSONATION",
    reason="기관 사칭 표현 감지",
    weight=35,
    keywords=(
        "검찰", "검사입니다", "수사관", "경찰청",
        "국민연금공단",      # ← 이렇게 추가
    ),
),
```

가중치는 **범주당 한 번만** 더해진다. 같은 범주에 키워드를 10개 넣어도 점수는
`weight` 한 번이다. 점수를 올리고 싶으면 `weight`를 올려야 한다.

확인:
```powershell
pytest backend\tests\test_rules.py
python -c "import sys; sys.path.insert(0,'backend'); from analysis.rules import analyze_message; r=analyze_message('국민연금공단입니다. 지금 바로 현금을 인출하세요'); print(r.risk_level, r.risk_score, r.reasons)"
```

| 언제 | 출력 |
|---|---|
| 키워드 추가 **전** | `CAUTION 45 ['현금 인출 요구 감지', '긴급 행동 요구 감지']` |
| 키워드 추가 **후** | `DANGER 80 ['기관 사칭 표현 감지', '현금 인출 요구 감지', '긴급 행동 요구 감지']` |

기관 사칭 범주의 가중치 35점이 더해져 45 → 80으로 올라가면서 CAUTION이 DANGER가 된다.
이렇게 **바뀌기 전과 후를 둘 다 눈으로 확인**하는 게 수정이 실제로 먹혔다는 증거다.

> 새 키워드를 넣었으면 **정상 문자도 꼭 같이 돌려 본다.** "긴급"처럼 흔한 낱말을
> 넣으면 정상 문자가 위험으로 잡히는 오탐이 생긴다(PRD 14.3의 가장 큰 위험 요소).

### 레시피 B — 위험 등급 경계값 바꾸기

`backend/config.py` 한 곳만 고치면 백엔드·ATM·화면 전부에 반영된다.

```python
RISK_SAFE_MAX = 29        # 이 값 이하면 SAFE
RISK_CAUTION_MAX = 69     # 이 값 이하면 CAUTION, 넘으면 DANGER
```

**같이 고쳐야 하는 곳**: `backend/tests/test_rules.py`의
`test_risk_level_boundaries` 파라미터. 안 고치면 테스트가 빨갛게 뜬다 — 이건
버그가 아니라 "확정 규칙을 바꿨다"는 신호이니 테스트도 함께 바꾸는 게 맞다.

### 레시피 C — 화면 문구 바꾸기

ATM 화면과 결과 화면의 문구는 각각 `GUIDANCE`라는 딕셔너리 한 곳에 모여 있다.

```python
# pi/atm_controller.py
GUIDANCE: dict[str, str] = {
    STATE_READY: "휴대폰 화면의 QR 코드를 카메라에 보여 주세요",
    STATE_WITHDRAW_BLOCKED: "보이스피싱 위험이 확인되어 현금 출금을 잠시 멈췄습니다",
    ...
}
```

노약자 대상이므로 문구를 바꿀 때 지킬 것: **짧게, 쉬운 말로, 다음에 뭘 해야 하는지**.
전문용어(세션, 검증, 토큰)를 화면에 노출하지 않는다.

## 4-3. 고칠 때 지키는 3가지

1. **요청과 관련된 줄만 건드린다.** 눈에 거슬리는 다른 코드는 그대로 둔다
   (`.agents/rules/karpathy-principles.md` 외과적 변경).
2. **고치기 전에 `pytest`를 한 번 돌려 초록인 걸 확인하고, 고친 뒤 다시 돌린다.**
   그래야 내가 깨뜨린 건지 원래 깨져 있던 건지 구분된다.
3. **커밋 전 확인** (`.agents/hooks/pre-commit-checklist.md`)
   ```powershell
   git diff --cached --name-only     # .env가 섞이지 않았는가
   git diff --cached                  # 하드코딩된 키·비밀번호가 없는가
   ```
   커밋 메시지는 `[역할] 무엇을 했는지` 형태로 쓴다. 예: `[backend] 기관 사칭 키워드 3개 추가`

## 4-4. 절대 무너뜨리면 안 되는 선

이 작품의 핵심 요구사항(FR-09)이다. 아래 테스트가 빨개지면 **무슨 일이 있어도
그 커밋은 하지 않는다.**

```powershell
pytest pi\tests\test_atm_controller.py::test_danger_qr_blocks_withdrawal_and_never_moves_servo
```

배출 여부 판단은 `pi/atm_controller.py`의 `request_withdraw()` **한 곳에만** 둔다.
다른 곳에서 `set_actuator_state(CASH_DISPENSER_DEVICE_ID, ...)`를 직접 부르는 코드를
만들면 이 방어선이 뚫린다.

# 5부. 기능 추가 방법

## 5-1. 절차 (하네스 workflow)

`.agents/workflows/feature-development.md`를 그대로 따른다.

1. **성공 기준을 먼저 한 문장으로 쓴다.**
   "부저 추가해줘"(❌) → "DANGER로 판정되면 ATM 부저가 2초간 울리고, SAFE면 안 울린다"(⭕)
2. **역할을 지정한 프롬프트로 AI에게 요청한다** (아래 틀)
3. **직접 실행해서 눈으로 확인한다** — AI의 요약만 믿지 않는다
4. **`pytest`로 기존 기능이 안 깨졌는지 본다**
5. **성공 기준을 실제로 만족하는지 다시 본다**
6. **커밋한다**

## 5-2. AI에게 줄 프롬프트 틀

```
너는 이 프로젝트의 [역할]-agent다.
.agents/rules/[관련 rule].md와 .agents/skills/[관련 스킬]/SKILL.md를 따른다.

[성공 기준을 문장으로]

관련 파일: [경로]
```

역할과 담당 영역:

| 역할 | 담당 | 항상 참고하는 규칙 |
|---|---|---|
| `backend-agent` | `backend/routers/`, `backend/analysis/`, `backend/schemas/` | `api-rules.md` |
| `db-agent` | `backend/db/` | `db-rules.md` |
| `frontend-agent` | `frontend/` | `ui-ux-rules.md` |
| `hardware-agent` | `backend/iot/`, `pi/` | `hardware-rules.md` |
| `security-reviewer` | 검토 전용 (코드 수정 안 함) | `security-rules.md`, `api-rules.md` |

## 5-5. 예시 C — 새 API 엔드포인트 추가

`.agents/skills/iot-endpoint-generator/SKILL.md`의 4단계를 그대로 따른다.

2. **Pydantic 모델** — `backend/schemas/models.py`에 요청·응답 스키마
3. **엔드포인트** — `backend/routers/` 아래 적절한 파일

## 5-7. 외부 AI API 연결 (PRD의 다음 단계)

PRD가 정한 순서는 **규칙 기반으로 전체 흐름을 완성한 뒤 AI를 붙이는 것**이고,
지금 그 1단계가 끝난 상태다. 붙일 때 반드시 지킬 것:

- 규칙 기반 엔진(`backend/analysis/rules.py`)을 **지우지 않는다.** 외부 AI 호출이
  실패하거나 인터넷이 끊겨도 시연이 이어져야 한다(PRD 11.3)
- `analysis_results.engine` 컬럼에 `rule` / `ai` 중 무엇으로 판정했는지 남긴다
  (이미 컬럼이 있다)
- API 키는 `backend/.env`에만 넣는다. 코드에 하드코딩하지 않는다
- 붙인 뒤 정상 문자·피싱 문자로 규칙 기반 결과와 비교해 오탐·미탐을 확인한다

```
너는 이 프로젝트의 backend-agent다. .agents/rules/security-rules.md를 따른다.

backend/analysis/에 외부 AI 판정 모듈을 추가해줘. 성공 기준은 이렇다:
- .env에 AI 키가 없거나 호출이 실패하면 지금의 규칙 기반 결과를 그대로 쓴다
- 성공하면 analysis_results.engine에 'ai'를 기록한다
- 출력 형식(risk_level / risk_score / reasons)은 지금과 똑같이 유지한다
- 기존 pytest 49개가 전부 통과해야 한다
```

# 6부. 윈도우 트러블슈팅

| 증상 | 해결 |
|---|---|
| `Activate.ps1` 실행 불가 (`PSSecurityException`) | `Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser` |
| `py`나 `python`이 없다고 나옴 | Python 재설치 시 "Add python.exe to PATH" 체크. PowerShell을 새로 연다 |
| 한글이 `???`나 깨진 글자로 나옴 | `chcp 65001` 실행 후 `$env:PYTHONUTF8 = "1"` |
| `ModuleNotFoundError: No module named 'fastapi'` | 가상환경을 활성화하지 않았다. 프롬프트 앞 `(venv)` 확인 |
| 포트 8000이 이미 사용 중 | `netstat -ano \| findstr :8000` → 나온 PID로 `taskkill /PID <번호> /F` |
| 화면은 뜨는데 목록이 비어 있다 | CORS. `backend\.env`의 `CORS_ORIGINS`와 브라우저 주소를 똑같이 맞춘다 (`localhost` ≠ `127.0.0.1`) |
| 로그인이 계속 401 | `python -m db.seed`를 안 돌렸거나 비밀번호가 다르다 |
| 콜센터 화면이 403 | `halmeoni`가 아니라 `callcenter` 계정으로 로그인해야 한다 (의도된 동작) |
| ATM API가 401 | `pi\.env`와 `backend\.env`의 `DEVICE_API_KEY`가 다르다 |
| `mysql: command not found` | `C:\xampp\mysql\bin\mysql.exe`를 전체 경로로 쓰거나 phpMyAdmin SQL 탭 사용 |
| `Get-Content ... \| mysql`에서 인코딩 오류 | phpMyAdmin SQL 탭에 붙여넣어 실행한다 |
| `pytest`에서 `No module named 'requests'` | `pip install -r pi\requirements.txt`를 안 했다 |
| `pi/tests/test_qr_end_to_end.py`가 skip됨 | `pip install opencv-python "qrcode[pil]"` |
| 카메라를 못 연다 | Zoom·Teams·브라우저 등 웹캠 점유 프로그램을 전부 종료. 안 되면 `ENABLE_CAMERA=false`로 두고 `POST /qr`로 검증 |
| 브라우저에 `ChunkLoadError` | 예전 `npm run dev` 프로세스가 남아 있다. 전부 닫고 `frontend\.next` 폴더를 지운 뒤 다시 실행 |
| `git push`가 안 됨 | GitHub 계정 권한과 브랜치 이름(`atm`)을 확인한다 |
