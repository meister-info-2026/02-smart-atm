> 추가하는** 방법을 다룬다. 명령은 전부 **PowerShell** 기준이다.

> 프로그램(`pi/main.py`)과 브라우저 화면(`/atm`)이 대신한다.

## 1-2. PowerShell 실행 정책 풀기 (가장 먼저)

이걸 안 하면 가상환경 활성화(`Activate.ps1`)가 `PSSecurityException`으로 막힌다.
PowerShell을 열고 **딱 한 번만** 실행한다.

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

한글 출력이 깨지면 같은 창에서:

```powershell
chcp 65001
$env:PYTHONUTF8 = "1"
```

## 1-4. 파이썬 가상환경 하나로 통합 (권장)

백엔드와 ATM 데몬을 한 PC에서 같이 개발하므로, **저장소 루트에 가상환경 하나**를
만들고 두 requirements를 함께 설치하는 게 가장 편하다. (라즈베리파이 실기기에는
`pi/requirements.txt`만 따로 설치한다 —
`docs/02_스마트금융보안ATM-실행-가이드.md` 4-2절 참고)

```powershell
# 저장소 루트에서
py -3.11 -m venv venv     # 3.12를 쓴다면 py -3.12, 버전이 하나뿐이면 그냥 py
.\venv\Scripts\Activate.ps1

python -m pip install --upgrade pip
pip install -r backend\requirements.txt -r pi\requirements.txt
pip install "qrcode[pil]"      # QR 이미지 생성 — 테스트와 시연 검증 스크립트에서 쓴다
```

프롬프트 앞에 `(venv)`가 붙으면 성공이다. **새 PowerShell 창을 열 때마다**
`.\venv\Scripts\Activate.ps1`을 다시 실행해야 한다.

설치 확인:

```powershell
python -c "import fastapi, sqlalchemy, cv2, qrcode, requests; print('OK')"
```

## 1-6. MySQL 데이터베이스 만들기

```powershell
Get-Content backend\db\init.sql | mysql -u root
```

`mysql: command not found`가 나면 둘 중 하나로 한다.

```powershell
# 방법 A — 전체 경로 지정
Get-Content backend\db\init.sql | & "C:\xampp\mysql\bin\mysql.exe" -u root
```

**방법 B (가장 확실함)** — 브라우저에서 `http://localhost/phpmyadmin` → **SQL 탭** →

`atm_sessions`, `devices` 등 9개 테이블이 보이면 된다.

## 1-7. `.env` 파일 3개 만들기

```powershell
Copy-Item backend\.env.example  backend\.env
Copy-Item frontend\.env.example frontend\.env.local
Copy-Item pi\.env.example       pi\.env
```

직접 만들어 넣어야 하는 값 두 개를 생성한다.

```powershell
# JWT_SECRET (32바이트 이상)
python -c "import secrets; print(secrets.token_urlsafe(48))"

# DEVICE_API_KEY
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

세 파일을 메모장이나 VS Code로 열어 채운다.

**`backend\.env`**
```ini
DEVICE_MODE=mock
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root
DB_PASSWORD=            # XAMPP 기본값은 비어 있다
DB_NAME=smart_atm
JWT_SECRET=<위에서 만든 첫 번째 값>
DEVICE_API_KEY=<위에서 만든 두 번째 값>
CORS_ORIGINS=http://localhost:3000
SEED_DEFAULT_PASSWORD=      # 비워두면 demo1234
```

**`pi\.env`** — PC에서 개발할 때는 일단 카메라 없이 돌린다.
(PC 웹캠이 있으면 나중에 3-4를 보고 `ENABLE_CAMERA=true`로 켤 수 있다.)
```ini
BACKEND_URL=http://127.0.0.1:8000
DEVICE_API_KEY=<backend\.env와 똑같은 값>
DEVICE_MODE=mock
ENABLE_CAMERA=false
ATM_DAEMON_PORT=8100
CALL_CENTER_POLL_SECONDS=3
IDLE_RESET_SECONDS=60
```

> ⚠️ **`BACKEND_URL`은 반드시 `http://127.0.0.1:8000`으로 둔다.** `pi\.env.example`의
> 예전 버전에는 라즈베리파이용 주소(`http://192.168.0.100:8000`)가 기본값으로 들어
> 있었다. 그 값이 남아 있으면 ATM 데몬이 백엔드를 못 찾아, 화면은 멀쩡한데 **QR을
> 넣어도 아무 반응이 없다**(3-2절 "실패 6건" 참고).
>
> ⚠️ **`.env`를 고친 뒤에는 그 서버를 껐다 다시 켠다.** `.env`는 프로그램이 시작할 때
> 한 번만 읽는다. 값만 고치고 창을 그대로 두면 아무것도 달라지지 않는다.

**`frontend\.env.local`** — 기본값 그대로 두면 된다.
```ini
NEXT_PUBLIC_API_BASE_URL=http://localhost:8000
NEXT_PUBLIC_WS_URL=ws://localhost:8000/ws
NEXT_PUBLIC_ATM_DAEMON_URL=http://localhost:8100
```

> ⚠️ `CORS_ORIGINS`의 주소와 브라우저 주소창의 주소를 **똑같이** 맞춘다.
> `localhost`와 `127.0.0.1`은 브라우저가 서로 다른 출처로 취급한다. 어긋나면
> 화면은 뜨는데 목록만 계속 비어 있다.
>
> ⚠️ `.env` 파일은 커밋되지 않는다(`.gitignore`). 실제 시크릿 값을 AI 채팅창에
> 붙여넣지 않는다 — 한 번이라도 붙여넣었으면 새로 만든다.

# 3부. 테스트 방법

테스트는 **성격이 다른 3가지**가 있다. 셋을 섞지 않는 것이 중요하다.

| 무엇 | 언제 쓰나 | 무엇을 확인하나 | 어디에 |
|---|---|---|---|
| **① 자동 테스트** (`pytest`) | 코드를 고칠 때마다 | 판정 규칙·API·차단 로직이 안 깨졌는지 | 3-1 |
| **② 통합 시연 검증** (`demo_e2e.py`) | 서버를 다 띄운 뒤 | 화면 없이 전체 흐름이 이어지는지 | 3-2 |
| **③ 수동 시연** (손으로 클릭) | 발표·전시회 | 사람이 보는 화면과 순서 | 3-3 · **전시회 매뉴얼** |

> ⚠️ **작품 전시회 당일에는 ①②를 쓰지 않는다.** 관람객 앞에서는 100% 손으로
> 조작하는 시연으로 진행한다. 당일 절차는 `docs/04_전시회-시연-매뉴얼.md`에 따로 있다.
> ①②는 **전날 밤 "내 코드가 성한지" 확인하는 용도**다.

## 3-1. 자동 테스트 — 서버를 안 띄워도 된다

저장소 **루트**에서:

```powershell
.\venv\Scripts\Activate.ps1
pytest
```

### 성공 판단 — 마지막 줄 하나만 본다

```
84 passed, 1 warning in 6.7s
```

`failed`라는 단어가 **없으면** 성공이다. 중간에 지나가는 점(`......`)과
`warning` 1건은 정상이다 — 경고는 라이브러리가 알려주는 안내일 뿐 우리 코드 문제가
아니다.

### 실패 판단 — 5곳만 읽으면 된다

예를 들어 `backend/config.py`의 위험 등급 경계값을 잘못 바꾸면 이렇게 나온다.

```
____________________ test_risk_level_boundaries[30-CAUTION] ____________________   ← ①

>       assert score_to_risk_level(score) == expected
E       AssertionError: assert 'SAFE' == 'CAUTION'                                  ← ②
E         - CAUTION                                                                 ← ③
E         + SAFE                                                                    ← ④

backend/tests/test_rules.py:67: AssertionError                                      ← ⑤

FAILED backend/tests/test_rules.py::test_risk_level_boundaries[30-CAUTION]
1 failed, 83 passed, 1 warning in 6.9s
```

| 표시 | 읽는 법 |
|---|---|
| ① | **어떤 약속이 깨졌는가.** `[30-CAUTION]`은 "30점을 넣으면 CAUTION이어야 한다"는 뜻 |
| ② | 무엇을 기대했고 무엇이 나왔는가 |
| ③ `-` | **기대한 값** — CAUTION이 나왔어야 한다 |
| ④ `+` | **실제 나온 값** — SAFE가 나왔다 |
| ⑤ | 테스트 코드의 위치 (파일:줄) |

> **⑤를 고치면 안 된다.** ⑤는 약속을 검사하는 쪽이고, 깨진 것은 **내가 방금 고친
> 소스 코드**다. 위 예에서 진짜 원인은 `backend/config.py`의 `RISK_SAFE_MAX` 값이다.
> 테스트를 고쳐서 초록불을 만드는 것은 **고장을 숨기는 것**이다.

### 실패했을 때 이 순서로 좁힌다

1. 마지막 줄에서 **몇 개가 깨졌는지** 본다
   - `1 failed` ~ `3 failed` → 방금 고친 코드가 원인일 가능성이 높다
   - `20 failed` 처럼 대부분 실패 → 코드가 아니라 **설치·환경 문제**다. 1부로 돌아간다
2. `FAILED` 줄의 **파일명**으로 어느 영역인지 안다 (아래 표)
3. `git diff` 로 **내가 방금 무엇을 바꿨는지** 본다 — 원인은 거의 항상 여기 있다
4. 못 고치겠으면 `git checkout <파일명>` 으로 되돌리고 처음부터 다시 한다

### 테스트가 시작조차 안 될 때

`passed`도 `failed`도 안 나오고 아래 같은 줄이 나오면, 테스트가 **한 개도 실행되지
않은 것**이다. 코드 문제가 아니라 환경 문제다.

```
ModuleNotFoundError: No module named 'fastapi'
```

→ 가상환경을 활성화하지 않았거나 설치가 덜 됐다. 프롬프트 앞에 `(venv)`가 있는지
확인하고 1-4절의 설치를 다시 한다.

| 파일 | 무엇을 지키는가 |
|---|---|
| `backend/tests/test_rules.py` | TC-01~TC-03, 위험 등급 경계값, CAUTION=VERIFY |
| `backend/tests/test_api_flow.py` | 인증 분리, 전체 API 흐름, TC-04·TC-05, 콜센터 권한 |
| `pi/tests/test_atm_controller.py` | **FR-09** — 위험 상태에서 배출 장치가 안 움직이는지 |
| `pi/tests/test_qr_end_to_end.py` | 실제 QR 이미지를 만들어 다시 읽는 왕복 검증 |
| `pi/tests/test_qr_scanner_backend.py` | PC 웹캠을 켤 때 Windows에서 카메라 백엔드를 고르는 규칙 |

자주 쓰는 형태:

```powershell
pytest backend\tests\test_rules.py           # 한 파일만
pytest -k "danger"                            # 이름에 danger가 들어간 것만
pytest -q                                     # 짧게
pytest -x                                     # 첫 실패에서 멈춤
pytest -vv --tb=long                          # 실패 원인 자세히
```

> 테스트는 임시 SQLite 파일을 쓴다. MySQL을 안 켜도 돌아가고, 실제 `smart_atm`
> 데이터베이스를 건드리지 않는다.

## 3-2. 통합 시연 검증 — 서버를 띄운 상태에서

창 1(백엔드)과 창 3(ATM 데몬)이 떠 있는 상태에서 **네 번째 창**을 열고:

```powershell
.\venv\Scripts\Activate.ps1
$env:DEVICE_API_KEY = "<backend\.env에 넣은 값>"
$env:SEED_DEFAULT_PASSWORD = "demo1234"
python scripts\demo_e2e.py
```

5개 시나리오를 순서대로 돌린다. 실제 QR PNG를 만들어 OpenCV로 다시 읽는 것까지 포함한다.

1. 정상 문자 → 출금 가능, 실제 배출
2. 보이스피싱 문자 → 출금 차단 → 콜센터 해제 → 배출
3. 잘못된 QR → 거래 제어에 사용 안 함
4. 사용자는 스스로 제한을 못 푼다
5. 인증 분리(디바이스 키 ↔ 사용자 JWT)

### 성공 판단 — 모든 줄이 `OK`, 마지막에 통과 문장

```
[시나리오 2] 보이스피싱 문자 → 출금 차단 → 콜센터 해제 (PRD 9.2 / TC-02·TC-05)
  OK   분석 결과가 DANGER — score=100
  OK   탐지 근거가 표시됨 (FR-04) — 기관 사칭 표현 감지, 범죄 연루 언급 감지, ...
  OK   ATM이 출금 제한 상태로 전환 (FR-07)
  OK   출금 버튼을 눌러도 배출되지 않음 (FR-09)
  ...
============================================================
통합 시연 전 구간 통과 — 정상 문자와 보이스피싱 문자 모두 확인했습니다.
```

### 실패 판단 — 두 가지 모양을 구분한다

**모양 1 — `FAIL` 줄이 섞여 있다**: 서버는 떠 있는데 동작이 기대와 다르다.
마지막에 실패한 항목만 모아서 보여준다.

```
실패 2건: ATM이 출금 제한 상태로 전환 (FR-07), 출금 버튼을 눌러도 배출되지 않음 (FR-09)
```

→ 먼저 `pytest`를 돌린다. 거기서도 깨지면 **로직 문제**이니 3-1로 간다.
`pytest`는 통과하는데 여기서만 깨지면 **서버 연결·`.env` 문제**다.

**모양 2 — `OK`도 `FAIL`도 없이 빨간 오류가 쏟아진다**: 서버가 안 떠 있다.
**맨 아랫줄의 포트 번호**만 보면 어느 창을 안 켰는지 바로 안다.

```
requests.exceptions.ConnectionError: HTTPConnectionPool(host='127.0.0.1', port=8000):
  Max retries exceeded with url: /api/v1/auth/login ... Connection refused
```
→ **포트 8000** = 창 1(백엔드)이 안 떠 있다

```
requests.exceptions.ConnectionError: HTTPConnectionPool(host='127.0.0.1', port=8100):
  Max retries exceeded with url: /reset ... Connection refused
```
→ **포트 8100** = 창 3(ATM 데몬)이 안 떠 있다

### 가장 흔한 실패 — **실패 6건이 이 조합**이면 데몬↔백엔드 통신이다

아래 6개가 한꺼번에 실패하고 나머지가 전부 `OK`라면, 원인은 **하나**다.

```
실패 6건: ATM이 출금 가능 상태로 전환, 현금이 실제로 배출됨 (FR-08),
ATM이 출금 제한 상태로 전환 (FR-07), 콜센터 확인 단계로 전환 (FR-11),
콜센터 해제 후 출금이 열림 (TC-05), 해제 후 현금 배출 성공
```

읽는 법은 이렇다. **QR을 넣었을 때 ATM 상태가 전혀 바뀌지 않는다**는 뜻이다.

| 통과하는 것 | 실패하는 것 |
|---|---|
| 문자 분석 (0점 / 100점 / 근거 4개) | QR → 출금 가능 전환 |
| 잘못된 QR 거부 | QR → 출금 차단 전환 |
| 콜센터 목록·권한 | 콜센터 전환 / 해제 반영 |

분석과 콜센터 API는 멀쩡한데 QR 처리만 전부 실패한다 — **스크립트↔백엔드는 되는데
데몬↔백엔드가 안 되는** 상태다.

> ⚠️ 이때 **`FR-09`(출금 버튼 눌러도 배출 안 됨)가 `OK`로 나오는 것은 착시다.**
> 애초에 출금이 열린 적이 없어서 통과한 것이지, 차단 기능이 동작한 것이 아니다.

**30초 확인 — 두 곳만 본다.**

① **창 3(ATM 데몬) 로그**. QR을 넣을 때마다 아래 줄이 찍힌다.

```
[WARNING] 서버 검증 실패, 로컬 판단으로 전환합니다: ...
```

② **`/state` 의 `offline` 값.**

```powershell
Invoke-RestMethod http://localhost:8100/state | Select-Object -ExpandProperty data
```

`offline: True` 면 데몬이 백엔드에 못 붙은 것이 확정이다.

**①의 메시지에 따라 원인이 갈린다.**

| 창 3 로그 | 원인 | 조치 |
|---|---|---|
| `401 Client Error: Unauthorized` | `pi\.env` ↔ `backend\.env` 의 `DEVICE_API_KEY` 불일치 | 두 값을 똑같이 맞춘다 |
| `백엔드에 연결하지 못했습니다: ...` | `pi\.env` 의 `BACKEND_URL` 이 잘못됐다 | `http://127.0.0.1:8000` 으로 바꾼다. **로그에 잘못된 주소가 그대로 찍히므로**(예: `host='192.168.0.100'`) 바로 확인된다 |

```powershell
Get-Content pi\.env      | Select-String "BACKEND_URL|DEVICE_API_KEY"
Get-Content backend\.env | Select-String "DEVICE_API_KEY"
```

> **⚠️ 고친 뒤 창 3을 반드시 재시작한다.** ATM 데몬은 `.env`를 **시작할 때 한 번만**
> 읽는다. 값만 고치고 데몬을 그대로 두면 **실패 6건이 똑같이 다시 난다.**
> 창 3에서 `Ctrl+C` → `python main.py` 를 다시 실행한 뒤 `demo_e2e.py`를 재실행한다.

### 이 스크립트가 못 잡는 것 — 스크립트에 넘긴 `DEVICE_API_KEY`

위 표와 헷갈리지 말 것 — 여기서 말하는 것은 **`$env:DEVICE_API_KEY`로 스크립트에
직접 넘긴 값**이다. 이 값이 틀려도 **스크립트는 "전 구간 통과"로 나온다**(시나리오 4의
마지막 검사가 401일 때 조용히 건너뛰기 때문이다). 즉 `demo_e2e.py`의 통과만으로
"키가 맞다"고 결론 내리면 안 된다.

정리하면 `DEVICE_API_KEY`는 쓰이는 곳이 둘이고, 증상이 서로 다르다.

| 어디의 키인가 | 틀리면 | 어떻게 아는가 |
|---|---|---|
| `pi\.env` (ATM 데몬이 쓴다) | **실패 6건** | 창 3 로그에 `401` |
| `$env:DEVICE_API_KEY` (스크립트가 쓴다) | 겉으로는 **통과** | 창 3 로그로는 안 보인다. 두 `.env`를 눈으로 비교한다 |

## 3-4. PC 웹캠으로 QR 인식까지 해 보기 (선택)

1-7의 `pi\.env`는 웹캠이 없는 PC에서도 막히지 않도록 `ENABLE_CAMERA=false`로
시작한다. 하지만 **PC에 웹캠이 있으면 라즈베리파이 없이도 실제 QR 인식까지 그대로
돌려 볼 수 있다.** 파이 전용 카메라 API(`picamera2`)를 쓰지 않고 OpenCV만 쓰기
때문에 `pi/qr_scanner.py` 코드가 Windows에서도 똑같이 동작한다.

### 1단계 — 인식만 따로 확인한다

ATM 데몬을 건드리기 전에, 웹캠이 QR을 읽는지부터 본다.

```powershell
.\venv\Scripts\Activate.ps1
python vision\qr_check.py
```

미리보기 창이 뜨면 `/messages`에서 문자를 검사해 나온 QR을 휴대폰이나 다른
모니터에 띄워 비춘다. 콘솔에 `→ session_id: VP-000003`이 찍히면 성공이다.
`q` 키로 닫는다.

노트북 내장캠 말고 USB 웹캠으로 읽고 싶으면 번호를 바꾼다:

```powershell
python vision\qr_check.py --camera 1
```

이미지 파일 한 장만 검사할 수도 있다: `python vision\qr_check.py sample.png`

### 2단계 — ATM 데몬에 카메라를 켠다

1단계가 되면 `pi\.env`를 고친다.

```ini
ENABLE_CAMERA=true
CAMERA_INDEX=0        # 1단계에서 통한 번호를 그대로 쓴다
```

창 3(ATM 데몬)을 껐다 다시 켜고 QR을 비추면 로그에
`카메라 열림 (index=0, backend=dshow)`과 `QR 인식: ...`이 찍히고 `/atm` 화면이
바뀐다. 이때부터는 3-3 체크리스트의 `Invoke-RestMethod ... /qr` 단계를 건너뛰고
실제로 QR을 비추면 된다.

> 카메라를 못 열어도 ATM 데몬은 죽지 않는다. 에러만 로그에 남기고 계속 떠 있으므로
> `POST /qr` 백업 절차를 그대로 쓸 수 있다.

### 웹캠을 쓸 때 걸리는 함정 2가지

| 함정 | 왜 생기나 / 어떻게 푸나 |
|---|---|
| 카메라 여는 데 5~10초가 걸리거나 아무 메시지 없이 실패한다 | Windows의 OpenCV 기본 백엔드(MSMF)에서 흔한 증상이다. 그래서 코드가 Windows에서는 DSHOW를 **먼저** 시도하고 안 되면 기본값으로 되돌아간다. 로그의 `backend=` 값으로 무엇이 잡혔는지 알 수 있고, `pi\.env`에 `CAMERA_BACKEND=msmf`처럼 적어 하나로 고정할 수도 있다 (`auto`/`dshow`/`msmf`/`v4l2`/`any`) |
| 한쪽에서만 카메라가 안 열린다 | 웹캠은 한 번에 한 프로그램만 쓴다. `vision\qr_check.py`와 ATM 데몬을 **동시에** 켜면 나중에 뜬 쪽이 실패한다. Zoom·Teams·브라우저 탭도 마찬가지다 — 하나씩 쓴다 |

> 실기기(라즈베리파이 5)에서는 `CAMERA_BACKEND=auto`가 리눅스 기본 백엔드를 그대로
> 쓰므로 지금까지와 달라지는 것이 없다.

## 4-2. 수정 레시피 3가지

### 레시피 A — 위험 키워드 추가하기

가장 자주 하게 될 수정이다. `backend/analysis/keywords.py`에서 해당 범주의
`keywords` 튜플에 문자열만 추가한다.

```python
RiskCategory(
    code="IMPERSONATION",
    reason="기관 사칭 표현 감지",
    weight=35,
    keywords=(
        "검찰", "검사입니다", "수사관", "경찰청",
        "국민연금공단",      # ← 이렇게 추가
    ),
),
```

가중치는 **범주당 한 번만** 더해진다. 같은 범주에 키워드를 10개 넣어도 점수는
`weight` 한 번이다. 점수를 올리고 싶으면 `weight`를 올려야 한다.

확인:
```powershell
pytest backend\tests\test_rules.py
python -c "import sys; sys.path.insert(0,'backend'); from analysis.rules import analyze_message; r=analyze_message('국민연금공단입니다. 지금 바로 현금을 인출하세요'); print(r.risk_level, r.risk_score, r.reasons)"
```

| 언제 | 출력 |
|---|---|
| 키워드 추가 **전** | `CAUTION 45 ['현금 인출 요구 감지', '긴급 행동 요구 감지']` |
| 키워드 추가 **후** | `DANGER 80 ['기관 사칭 표현 감지', '현금 인출 요구 감지', '긴급 행동 요구 감지']` |

기관 사칭 범주의 가중치 35점이 더해져 45 → 80으로 올라가면서 CAUTION이 DANGER가 된다.
이렇게 **바뀌기 전과 후를 둘 다 눈으로 확인**하는 게 수정이 실제로 먹혔다는 증거다.

> 새 키워드를 넣었으면 **정상 문자도 꼭 같이 돌려 본다.** "긴급"처럼 흔한 낱말을
> 넣으면 정상 문자가 위험으로 잡히는 오탐이 생긴다(PRD 14.3의 가장 큰 위험 요소).

### 레시피 B — 위험 등급 경계값 바꾸기

`backend/config.py` 한 곳만 고치면 백엔드·ATM·화면 전부에 반영된다.

```python
RISK_SAFE_MAX = 29        # 이 값 이하면 SAFE
RISK_CAUTION_MAX = 69     # 이 값 이하면 CAUTION, 넘으면 DANGER
```

**같이 고쳐야 하는 곳**: `backend/tests/test_rules.py`의
`test_risk_level_boundaries` 파라미터. 안 고치면 테스트가 빨갛게 뜬다 — 이건
버그가 아니라 "확정 규칙을 바꿨다"는 신호이니 테스트도 함께 바꾸는 게 맞다.

### 레시피 C — 화면 문구 바꾸기

ATM 화면과 결과 화면의 문구는 각각 `GUIDANCE`라는 딕셔너리 한 곳에 모여 있다.

```python
# pi/atm_controller.py
GUIDANCE: dict[str, str] = {
    STATE_READY: "출금하실 금액을 선택해 주세요",   # 평상시에도 출금은 열려 있다
    STATE_WITHDRAW_BLOCKED: "보이스피싱 위험이 확인되어 현금 출금을 잠시 멈췄습니다",
    ...
}
```

노약자 대상이므로 문구를 바꿀 때 지킬 것: **짧게, 쉬운 말로, 다음에 뭘 해야 하는지**.
전문용어(세션, 검증, 토큰)를 화면에 노출하지 않는다.

## 4-3. 고칠 때 지키는 3가지

1. **요청과 관련된 줄만 건드린다.** 눈에 거슬리는 다른 코드는 그대로 둔다
   (`.agents/rules/karpathy-principles.md` 외과적 변경).
2. **고치기 전에 `pytest`를 한 번 돌려 초록인 걸 확인하고, 고친 뒤 다시 돌린다.**
   그래야 내가 깨뜨린 건지 원래 깨져 있던 건지 구분된다.
3. **커밋 전 확인** (`.agents/hooks/pre-commit-checklist.md`)
   ```powershell
   git diff --cached --name-only     # .env가 섞이지 않았는가
   git diff --cached                  # 하드코딩된 키·비밀번호가 없는가
   ```
   커밋 메시지는 `[역할] 무엇을 했는지` 형태로 쓴다. 예: `[backend] 기관 사칭 키워드 3개 추가`

## 4-4. 절대 무너뜨리면 안 되는 선

이 작품의 핵심 요구사항(FR-09)이다. 아래 테스트가 빨개지면 **무슨 일이 있어도
그 커밋은 하지 않는다.**

```powershell
pytest pi\tests\test_atm_controller.py::test_danger_qr_blocks_withdrawal_and_never_moves_servo
```

배출 여부 판단은 `pi/atm_controller.py`의 `request_withdraw()` **한 곳에만** 둔다.
다른 곳에서 `set_actuator_state(CASH_DISPENSER_DEVICE_ID, ...)`를 직접 부르는 코드를
만들면 이 방어선이 뚫린다.

같은 무게로 지켜야 하는 선이 셋 더 있다. 전부 "돈이 잘못 나가는" 경로다.

| 지켜야 할 것 | 왜 | 지키는 테스트 |
|---|---|---|
| 확인하지 못했으면 내주지 않는다 | 디바이스 키가 틀리면 서버에 못 물어본다. 그 상태에서 그냥 내주면 **보호 장치가 꺼진 걸 아무도 모른 채** 위조 QR에 돈이 나간다. '확인 못 함'은 '안전함'이 아니다 | `test_auth_failure_never_falls_back_to_qr_claim` |
| 서버가 대답했으면 QR을 믿지 않는다 | 로컬 판단으로 넘어가는 경우는 **서버에 닿지 못했을 때 하나뿐**이다. 서버가 401로 대답했는데 QR이 스스로 적어 온 등급을 믿으면 그건 검증이 아니다 | `test_unexpected_backend_error_does_not_open_withdrawal` |
| 디바이스가 스스로 제한을 풀 수 없다 | ATM이 `WITHDRAW_ENABLED`를 보고하는 것만으로 DANGER가 풀리면, 사람의 확인을 거치게 한 설계 자체가 무의미해진다 | `test_device_cannot_open_withdrawal_without_callcenter` |

반대로 **평상시(READY)에 돈이 나오는 것은 버그가 아니라 설계다.** ATM은 공용
기계이고, 그 앞에 선 사람은 이 시스템과 아무 상관 없을 수도 있다. 막는 대상은
'확인되지 않은 사람'이 아니라 '위험이 확인된 세션'이다.

# 5부. 기능 추가 방법

## 5-1. 절차 (하네스 workflow)

`.agents/workflows/feature-development.md`를 그대로 따른다.

1. **성공 기준을 먼저 한 문장으로 쓴다.**
   "부저 추가해줘"(❌) → "DANGER로 판정되면 ATM 부저가 2초간 울리고, SAFE면 안 울린다"(⭕)
2. **역할을 지정한 프롬프트로 AI에게 요청한다** (아래 틀)
3. **직접 실행해서 눈으로 확인한다** — AI의 요약만 믿지 않는다
4. **`pytest`로 기존 기능이 안 깨졌는지 본다**
5. **성공 기준을 실제로 만족하는지 다시 본다**
6. **커밋한다**

## 5-2. AI에게 줄 프롬프트 틀

```
너는 이 프로젝트의 [역할]-agent다.
.agents/rules/[관련 rule].md와 .agents/skills/[관련 스킬]/SKILL.md를 따른다.

[성공 기준을 문장으로]

관련 파일: [경로]
```

역할과 담당 영역:

| 역할 | 담당 | 항상 참고하는 규칙 |
|---|---|---|
| `backend-agent` | `backend/routers/`, `backend/analysis/`, `backend/schemas/` | `api-rules.md` |
| `db-agent` | `backend/db/` | `db-rules.md` |
| `frontend-agent` | `frontend/` | `ui-ux-rules.md` |
| `hardware-agent` | `backend/iot/`, `pi/` | `hardware-rules.md` |
| `security-reviewer` | 검토 전용 (코드 수정 안 함) | `security-rules.md`, `api-rules.md` |

## 5-7. 외부 AI API 연결 (PRD의 다음 단계)

PRD가 정한 순서는 **규칙 기반으로 전체 흐름을 완성한 뒤 AI를 붙이는 것**이고,
지금 그 1단계가 끝난 상태다. 붙일 때 반드시 지킬 것:

- 규칙 기반 엔진(`backend/analysis/rules.py`)을 **지우지 않는다.** 외부 AI 호출이
  실패하거나 인터넷이 끊겨도 시연이 이어져야 한다(PRD 11.3)
- `analysis_results.engine` 컬럼에 `rule` / `ai` 중 무엇으로 판정했는지 남긴다
  (이미 컬럼이 있다)
- API 키는 `backend/.env`에만 넣는다. 코드에 하드코딩하지 않는다
- 붙인 뒤 정상 문자·피싱 문자로 규칙 기반 결과와 비교해 오탐·미탐을 확인한다

```
너는 이 프로젝트의 backend-agent다. .agents/rules/security-rules.md를 따른다.

backend/analysis/에 외부 AI 판정 모듈을 추가해줘. 성공 기준은 이렇다:
- .env에 AI 키가 없거나 호출이 실패하면 지금의 규칙 기반 결과를 그대로 쓴다
- 성공하면 analysis_results.engine에 'ai'를 기록한다
- 출력 형식(risk_level / risk_score / reasons)은 지금과 똑같이 유지한다
- 기존 pytest 49개가 전부 통과해야 한다
```

# 6부. 윈도우 트러블슈팅

| 증상 | 해결 |
|---|---|
| `Activate.ps1` 실행 불가 (`PSSecurityException`) | `Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser` |
| `py`나 `python`이 없다고 나옴 | Python 재설치 시 "Add python.exe to PATH" 체크. PowerShell을 새로 연다 |
| 한글이 `???`나 깨진 글자로 나옴 | `chcp 65001` 실행 후 `$env:PYTHONUTF8 = "1"` |
| `pip install -r requirements.txt`에서 `UnicodeDecodeError: 'cp949' codec can't decode byte 0xeb` | pip 24.x가 한글 주석이 든 `requirements.txt`를 시스템 인코딩(cp949)으로 읽어서 생긴다. 저장소의 requirements 파일에는 첫 줄에 `# -*- coding: utf-8 -*-`가 들어 있으니 `git pull`로 최신 코드를 받는다. 직접 만든 파일이라면 그 첫 줄을 맨 위에 넣거나, `python -m pip install --upgrade pip`로 pip를 25 버전 이상으로 올린다. |
| `ModuleNotFoundError: No module named 'fastapi'` | 가상환경을 활성화하지 않았다. 프롬프트 앞 `(venv)` 확인 |
| 포트 8000이 이미 사용 중 | `netstat -ano \| findstr :8000` → 나온 PID로 `taskkill /PID <번호> /F` |
| 화면은 뜨는데 목록이 비어 있다 | CORS. `backend\.env`의 `CORS_ORIGINS`와 브라우저 주소를 똑같이 맞춘다 (`localhost` ≠ `127.0.0.1`) |
| 로그인이 계속 401 | `python -m db.seed`를 안 돌렸거나 비밀번호가 다르다 |
| 콜센터 화면이 403 | `halmeoni`가 아니라 `callcenter` 계정으로 로그인해야 한다 (의도된 동작). 화면 오른쪽 위 **"계정 바꾸기"** 로 전환한다 |
| 로그인 화면이 처음 한 번만 뜨고 다시 안 뜬다 | 로그인 정보가 브라우저에 남아 있어서다. 화면 오른쪽 위 **"계정 바꾸기"** 를 누른다 |
| 두 계정을 동시에 쓰고 싶다 | 로그인 정보는 브라우저 하나에 하나만 저장된다. 상담원 화면은 **시크릿 창**(Ctrl+Shift+N)에서 열면 사용자 로그인과 따로 유지된다 |
| ATM API가 401 | `pi\.env`와 `backend\.env`의 `DEVICE_API_KEY`가 다르다 |
| QR을 넣어도 ATM 화면이 안 바뀐다 (`demo_e2e.py` 실패 6건) | ATM 데몬이 백엔드에 못 붙었다. 창 3 로그의 `서버 검증 실패...` 줄을 보고 `401`이면 `DEVICE_API_KEY`, `연결하지 못했습니다`면 `pi\.env`의 `BACKEND_URL`을 고친다 (3-2절) |
| `.env`를 고쳤는데 그대로다 | `.env`는 시작할 때 한 번만 읽는다. 해당 창을 `Ctrl+C`로 끄고 다시 실행한다 |
| `mysql: command not found` | `C:\xampp\mysql\bin\mysql.exe`를 전체 경로로 쓰거나 phpMyAdmin SQL 탭 사용 |
| `Get-Content ... \| mysql`에서 인코딩 오류 | phpMyAdmin SQL 탭에 붙여넣어 실행한다 |
| `pytest`에서 `No module named 'requests'` | `pip install -r pi\requirements.txt`를 안 했다 |
| `pi/tests/test_qr_end_to_end.py`가 skip됨 | `pip install opencv-python "qrcode[pil]"` |
| 카메라를 못 연다 | 웹캠은 한 번에 한 프로그램만 쓴다 — Zoom·Teams·브라우저와 `vision\qr_check.py`를 전부 종료. USB 웹캠이면 `pi\.env`의 `CAMERA_INDEX`를 1, 2로 바꾼다. 그래도 안 되면 `ENABLE_CAMERA=false`로 두고 `POST /qr`로 검증 (3-4 참고) |
| 카메라가 열리긴 하는데 5~10초씩 걸린다 | Windows 기본 백엔드(MSMF) 문제다. 로그의 `backend=` 값을 보고 `pi\.env`에 `CAMERA_BACKEND=dshow`로 고정한다 |
| 브라우저에 `ChunkLoadError` | 예전 `npm run dev` 프로세스가 남아 있다. 전부 닫고 `frontend\.next` 폴더를 지운 뒤 다시 실행 |
| `git push`가 안 됨 | GitHub 계정 권한과 브랜치 이름(`atm`)을 확인한다 |
